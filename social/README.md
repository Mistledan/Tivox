# TIVOX Social Automation

Dependency-free Node scripts that post TIVOX content to **Telegram, X, YouTube,
and TikTok**. Content angles rotate through `content/topics.json`; captions are
generated by an LLM when `OPENAI_API_KEY` is set, otherwise by the built-in
templates in `src/content.js`.

## How it works

- `src/index.js` — entry point; picks platforms, rotates topics, calls adapters.
- `src/content.js` — caption generation + platform length limits.
- `src/adapters/*.js` — one file per platform.
- `content/state.json` — rotation + history (committed back by the workflow).
- `content/topics.json` — the content angles to cycle through.
- `assets/videos/` — put `.mp4` files here for YouTube/TikTok posts.

## Run locally

```bash
cp social/.env.example social/.env   # then fill in what you have
node --env-file=social/.env social/src/index.js --dry-run
```

`--dry-run` generates and logs everything without calling any API — no keys needed.

Useful flags:

```bash
node social/src/index.js --dry-run                 # all platforms, no posting
node social/src/index.js --platforms=telegram      # one platform
node social/src/index.js --platforms=x,telegram    # several
```

## Platform setup

### Telegram (free, do this first)

1. Message [@BotFather](https://t.me/BotFather), run `/newbot`, copy the token.
2. Create a channel, add the bot as an admin.
3. Set `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` (the channel username like
   `@yourchannel`, or its numeric id).

### X / Twitter

Posting via the API **requires a paid tier** (the free tier is heavily limited).
1. Create a project/app at https://developer.x.com.
2. Set app permissions to **Read and write**.
3. Generate the consumer keys and an access token/secret for your account.
4. Set `X_CONSUMER_KEY`, `X_CONSUMER_SECRET`, `X_ACCESS_TOKEN`,
   `X_ACCESS_TOKEN_SECRET`.

### YouTube

Uploads require a one-time OAuth consent to obtain a refresh token.
1. Create an OAuth client (type: Desktop) in Google Cloud Console and enable the
   **YouTube Data API v3**.
2. Run the OAuth playground or a local flow with scope
   `https://www.googleapis.com/auth/youtube.upload` to get a refresh token.
3. Set `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_REFRESH_TOKEN`.
4. Drop an `.mp4` into `social/assets/videos/`. The first line of the caption
   becomes the title; the rest becomes the description.
5. Keep `YOUTUBE_PRIVACY_STATUS=private` until you trust it, then switch to `public`.

### TikTok

The Content Posting API needs an approved app before it will publish.
1. Create an app at https://developers.tiktok.com with the `video.publish` scope.
2. Complete the audit/approval process.
3. Set `TIKTOK_ACCESS_TOKEN`.
4. Until the app is audited, only `SELF_ONLY` posts are allowed — keep
   `TIKTOK_PRIVACY_LEVEL=SELF_ONLY`.

## Scheduling (GitHub Actions)

`.github/workflows/social.yml` runs every 6 hours and on demand. Add the values
above as repository secrets (**Settings → Secrets and variables → Actions**), then
run the workflow manually once with **dry_run = true** to confirm output.

## Content rules

The generator is instructed to never promise or imply returns, never guarantee
price, and always be honest about volatility while pointing to the official
contract address. Keep it that way — automated financial-promotion language gets
accounts banned fast.
